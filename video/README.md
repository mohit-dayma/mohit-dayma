# Memory series videos

Standalone [Remotion](https://www.remotion.dev/) 4 project for the videos that go
with the blog's memory series. It uses npm (not pnpm) and has its own
`package-lock.json`. The root `tsconfig.json` excludes this folder.

| Composition | What                                                           | Length |
| ----------- | -------------------------------------------------------------- | ------ |
| `Teaser`    | 31 s teaser for Part 1                                         | 0:31   |
| `Part1`     | Full explainer of "How CPU Caches Work: Memory Series, Part 1" | ~14:00 |

The rendered Part 1 video is committed at `renders/part-1.mp4`.

## Setup

```bash
cd video
npm ci
```

## Preview

```bash
npx remotion studio            # pick Teaser or Part1 in the sidebar
```

## Render

```bash
# Part 1 (1920x1080, 30 fps, with voiceover). Stays well under 90 MB at CRF 23.
npx remotion render Part1 out/part-1.mp4 --concurrency=4 --codec=h264 --crf=23 --audio-bitrate=96k
cp out/part-1.mp4 renders/part-1.mp4

# Teaser
npx remotion render Teaser out/teaser.mp4

# A single frame, for checking layout
npx remotion still Part1 out/frame.png --frame=1200

# Check the result
ffprobe -v error -show_entries format=duration,size -of default=nw=1 out/part-1.mp4
```

`out/` is git-ignored.

## How Part 1 is built

- `src/part1/narration.json` is the script: one entry per scene, one segment per
  caption. Segment ids double as cues that the scene components use to time
  their animations.
- `scripts/tts.py` voices every segment offline with
  [Piper](https://github.com/rhasspy/piper) (voice `en_US-lessac-medium`, no API
  key), joins each scene's segments with short pauses into
  `public/part1/audio/<scene>.mp3`, and writes the measured start and end of
  every segment to `src/part1/timings.json`.
- `src/part1/timeline.ts` turns those timings into frames. Each scene lasts as
  long as its audio, plus a chapter card before it.
- `src/part1/scenes/` has one file per scene. View components take props such as
  a step index or a 0–1 progress value, computed from the frame number. Every
  cache state on screen comes from the blog's own
  `src/components/mdx/memory/cache-model.ts`, so the video matches the widgets.
- `src/shared/` holds pieces used by both the teaser and Part 1 (fade and rise
  animations, the cache grid, the latency bars).
- `script/part-1.md` is a readable copy of the script with scene timings,
  generated by `scripts/script-md.py`.
- Geist and Geist Mono (SIL Open Font License) are bundled in `public/fonts`, so
  rendering does not need to reach Google Fonts.

### Changing the narration

```bash
python3 -m venv .venv && .venv/bin/pip install piper-tts
curl -LO https://huggingface.co/rhasspy/piper-voices/resolve/main/en/en_US/lessac/medium/en_US-lessac-medium.onnx
curl -LO https://huggingface.co/rhasspy/piper-voices/resolve/main/en/en_US/lessac/medium/en_US-lessac-medium.onnx.json
# edit src/part1/narration.json, then:
.venv/bin/python scripts/tts.py --piper .venv/bin/piper --model en_US-lessac-medium.onnx
python3 scripts/script-md.py
```

Spoken forms for terms the voice reads badly (L1d, SRAM, DDR5, ...) are in the
`SAY` table in `scripts/tts.py`; captions keep the written form.

### Recording a human voiceover instead

Record one file per scene, named like the files in `public/part1/audio/`, and
update the segment times in `src/part1/timings.json` (start and end of each
caption, in seconds from the start of that scene's file). Scene lengths,
captions and animations follow automatically.
